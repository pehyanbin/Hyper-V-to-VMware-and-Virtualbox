CRITICAL CHECKPOINT WARNING

If you see .avhd or .avhdx, stop before conversion.

Those files may be Hyper-V checkpoint/differencing disks. Converting only the base VHD can give you an older VM state. Resolve the disk chain first.

PHASE 00

Pre-flight checks

Do these once before choosing VMware or VirtualBox.

01

Understand the export

The target hypervisor does not reuse Hyper-V's VM configuration. The important migration asset is the virtual disk.

MyVM\ ├─ Virtual Machines\*.vmcx ├─ Virtual Hard Disks\MyVM.vhd └─ Snapshots\
02

Preserve the original

Keep the exported VHD untouched. Work from a copy and do not convert a disk that is currently in use by a running VM.

LAB CONFIGURATION CHECK

Before first boot

Verify all six required settings. The most important safety setting is that the VM has no usable network connection.

✓ Windows ✓ Windows 10 x64 ✓ BIOS ✓ Existing disk ✓ NO NETWORK ✓ 3D disabled
Malware-lab network rule

This lab VM must have NO NETWORK. Do not use NAT, Bridged, Host-only, or any other connected adapter. Disable/remove the virtual network adapter before booting the malware-analysis VM.

PHASE 01

Choose your target hypervisor

Each path starts from the exported .vhd and creates a new target-specific VM configuration.

PATH A

Hyper-V VHD → VMware VMDK

.VHD→.VMDK→.VMX
01

Inspect the exported disk

Confirm there is no unresolved .avhd/.avhdx chain, then make a backup of the VHD.

qemu-img.exe info "D:\HyperV-Export\Virtual Hard Disks\MyVM.vhd"

QEMU may report the VHD source format as vpc.

02

Download and test qemu-img.exe

The VMware workflow uses qemu-img to convert VHD → VMDK. Download it first, extract the archive, then test the executable.

DOWNLOAD QEMU-IMG FOR WINDOWS ↗ Cloudbase download page

qemu-img.exe --version

If it is not on PATH, run it with the full executable path.

03

Convert VHD → VMDK

qemu-img.exe convert -p -f vpc -O vmdk "D:\HyperV-Export\Virtual Hard Disks\MyVM.vhd" "D:\VMware\MyVM\MyVM_vmware.vmdk"
  • -p show progress
  • -f vpc source is VHD
  • -O vmdk output is VMDK
04

Verify the converted VMDK

qemu-img.exe info "D:\VMware\MyVM\MyVM_vmware.vmdk"

Confirm QEMU recognizes the new disk as vmdk before building the VM.

05

Create a new VMware VM

  1. Open VMware Workstation → File → New Virtual Machine.
  2. Select Custom (advanced).
  3. Choose I will install the operating system later.
  4. Guest operating system: Windows.
  5. Version: Windows 10 x64.
  6. Name the VM and choose a folder with enough free space.
Do not double-click the VMDK. A VMDK is the virtual disk. VMware opens the VM through the generated .vmx configuration.
06

Set CPU, RAM and disable networking

Start with approximately the same CPU count and RAM as the original VM. For this malware-analysis lab, networking must be disabled.

CPU≈ original vCPU count
RAM≈ original allocation
NETWORKNO NETWORK

In VMware, remove the network adapter or ensure it is disconnected before first boot.

07

Use the existing virtual disk

  1. On Select a Disk, choose Use an existing virtual disk.
  2. Browse to MyVM_vmware.vmdk.
  3. If asked whether to keep or convert the disk format, choose Keep Existing Format.
  4. Finish the wizard. VMware creates the .vmx.
08

Set firmware to BIOS

For this lab image, set the VMware firmware type to BIOS.

LAB FIRMWAREBIOS

Do not switch this lab VM to UEFI/EFI unless your instructor provides different settings.

09

Check disk, display and boot settings

Confirm the converted VMDK is attached under VM → Settings → Hard Disk and that the hard disk is available as a boot device.

Then open Display settings and disable 3D acceleration.

Required lab setting: 3D acceleration must be off before boot.
10

First boot and guest integration

The first Windows boot can take longer because the guest sees different virtual hardware. Let device detection finish.

  1. Install VMware Tools.
  2. Restart Windows.
  3. Check Device Manager for unknown devices or warning icons.
  4. Verify networking and Windows activation status.
11

Retain the source until validation is complete

Keep the original Hyper-V export, converted VMDK, and working VMware VM until you have verified boot, files, apps, network, services, and activation.

VMWARE CHAIN

Hyper-V export→check checkpoints→qemu-img→VMDK→new VMware VM→BIOS→NO NETWORK→3D OFF→VMX

PATH B

Hyper-V VHD → VirtualBox VDI

.VHD→.VDI→VirtualBox VM
01

Check the export and checkpoint state

Locate Virtual Hard Disks\MyVM.vhd. If any .avhd/.avhdx files exist, stop until the current disk state is identified.

02

Back up the VHD

Leave the original export untouched and create a separate working destination such as D:\VirtualBox\MyVM\.

03

Verify VBoxManage.exe — reinstall if missing

On Windows, VBoxManage.exe should be installed with the main VirtualBox application.

If VBoxManage.exe is missing: repair or reinstall the full VirtualBox package. Do not download VBoxManage.exe by itself.

DOWNLOAD VIRTUALBOX FOR WINDOWS ↗ Official Oracle downloads

& "C:\Program Files\Oracle\VirtualBox\VBoxManage.exe" --version

If VirtualBox.exe exists but VBoxManage.exe is missing, the guide recommends repairing/reinstalling VirtualBox rather than downloading the EXE separately.

04

Verify the VHD path

Test-Path "D:\Hyper-V Export\MyVM\Virtual Hard Disks\MyVM.vhd"

You want True. Paths containing spaces must remain quoted.

05

Convert VHD → VDI

& "C:\Program Files\Oracle\VirtualBox\VBoxManage.exe" clonemedium disk `
  "D:\Hyper-V Export\MyVM\Virtual Hard Disks\MyVM.vhd" `
  "D:\VirtualBox\MyVM\MyVM.vdi" --format VDI

The source PDF wraps the command across lines; PowerShell backticks continue the command onto the next line.

06

Verify the new VDI

Test-Path "D:\VirtualBox\MyVM\MyVM.vdi"
Get-Item "D:\VirtualBox\MyVM\MyVM.vdi" |
  Select-Object Name,Length,FullName
07

Create a new VirtualBox VM

  1. Open VirtualBox and click New.
  2. Guest OS: Windows.
  3. Version: Windows 10 (64-bit).
  4. Do not install Windows again.
  5. Set approximately the same RAM and CPU allocation as the original VM.
08

Attach the existing VDI

When prompted for a virtual hard disk, choose Use an Existing Virtual Hard Disk File and select your MyVM.vdi.

If the VM already exists: Settings → Storage → controller → Add Hard Disk → Existing Disk.

09

Use BIOS firmware for the lab VM

For this lab image, use BIOS. In VirtualBox, leave Enable EFI turned off.

LAB FIRMWAREBIOS / EFI OFF

The lab profile overrides the generic generation guidance in the source document.

10

Check storage, disable network and disable 3D

Confirm the VDI appears under Settings → Storage.

  1. Settings → Network: disable the network adapter completely. NO NETWORK.
  2. Settings → Display → Screen: disable 3D Acceleration.
Required lab settings: no network adapter and no 3D acceleration.
11

Start the VM and validate Windows

The first boot may take longer while Windows discovers VirtualBox virtual hardware. Let driver detection complete before troubleshooting aggressively.

12

Keep the original VHD

Do not delete the source VHD until the VirtualBox VM has been fully verified.

The supplied guide also notes that VirtualBox can use VHD directly, but recommends converting to VDI for this migration so the native VirtualBox disk is a separate copy.

VIRTUALBOX CHAIN

Hyper-V export→check checkpoints→VBoxManage→VDI→new VirtualBox VM→BIOS / EFI OFF→NO NETWORK→3D OFF

PHASE 02

Troubleshooting matrix

Check configuration and disk state before attempting operating-system repair.

VMWARE “VMDK cannot be opened directly”

Open the VM's .vmx, not the .vmdk. If a VMX does not exist, create a new VMware VM and choose the existing VMDK during the wizard.

VMWARE Operating system not found
  1. Confirm Hyper-V generation.
  2. Gen 1 → BIOS; Gen 2 → UEFI.
  3. Confirm the correct VMDK is attached.
  4. Confirm you did not convert only a base disk from a checkpoint chain.
VMWARE Windows Boot Manager missing

Verify firmware type, boot disk, VMDK attachment, partition/boot setup, and whether the converted disk represents the correct final Hyper-V state.

VMWARE VMDK will not open 
qemu-img.exe info "D:\VMware\MyVM\MyVM_vmware.vmdk"
VIRTUALBOX No bootable medium found
  1. For this lab VM, confirm EFI is disabled and BIOS-style boot is being used.
  2. Confirm the VDI is attached under Storage.
  3. Confirm Hard Disk is enabled in the boot order.
VIRTUALBOX VDI is inaccessible 
& "C:\Program Files\Oracle\VirtualBox\VBoxManage.exe" showmediuminfo
  "D:\VirtualBox\MyVM\MyVM.vdi"
BOTH Windows crashes after migration

The guest has moved to different virtual hardware. Check firmware, storage/controller configuration, attached disk, and guest drivers before assuming the disk image is damaged.
