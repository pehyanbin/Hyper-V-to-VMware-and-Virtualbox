HYPER-V SANDBOX MIGRATION PROTOCOL

_ INITIATING SEQUENCE... TARGET ENVIRONMENTS: VIRTUALBOX / VMWARE WORKSTATION

OBJECTIVE: Extract isolated virtual machines for dynamic malware analysis and reverse engineering sandboxes.

PHASE 0: RECON PHASE 1: VIRTUALBOX PHASE 2: VMWARE ANOMALY RESOLUTION

[ PHASE 0 ] RECONNAISSANCE & EXTRACTION

Before migrating the payload environment, we must verify the integrity of the Hyper-V export. A standard Hyper-V export contains virtual disks, configuration files, and potentially checkpoint files.

FILE TOPOLOGY:
.vmcx / .vmgs / .vmrs = Hyper-V Configuration (IGNORE THESE)
.vhd / .vhdx = Base Virtual Hard Disk (TARGET)
.avhd / .avhdx = Checkpoint / Differencing Disks (DANGER)

STEP 0.1: Verify Checkpoint Chains

Navigate to your export directory. Look inside Virtual Hard Disks\ and Snapshots\.

[!] CRITICAL WARNING: If you see .avhd or .avhdx files, STOP. These are differencing disks. Converting only the base .vhd will result in an outdated VM state. You must consolidate the disk chain in Hyper-V before exporting, or seek advanced chain-merging protocols.

STEP 0.2: Identify VM Generation

Determine if the source VM is Generation 1 (BIOS) or Generation 2 (UEFI). This dictates the firmware configuration in the target hypervisor.

powershell.exe
PS C:\> Get-VM "Target_VM" | Select-Object Name, Generation, State
Hyper-V GenFirmwareTarget Config
Generation 1BIOSLegacy BIOS
Generation 2UEFIEFI / Secure Boot

Note: Always create a backup of your original .vhd before executing conversion routines.

[ PHASE 1 ] VECTOR A: VIRTUALBOX PROTOCOL

VirtualBox utilizes the .vdi format natively. We will use the VBoxManage CLI utility to clone and convert the disk.

STEP 1.1: Verify VBoxManage Presence

Ensure the CLI tool is accessible. If missing, repair the VirtualBox installation via the official Oracle installer.

powershell.exe
PS C:\> & "C:\Program Files\Oracle\VirtualBox\VBoxManage.exe" --version

STEP 1.2: Execute Disk Conversion

Convert the .vhd to .vdi. Quotation marks are mandatory to handle directory spaces.

powershell.exe // conversion payload
PS C:\> & "C:\Program Files\Oracle\VirtualBox\VBoxManage.exe" clonemedium disk "D:\Hyper-V Export\MyVM\Virtual Hard Disks\MyVM.vhd" "D:\VirtualBox\MyVM\MyVM.vdi" --format VDI

STEP 1.3: VirtualBox VM Configuration

  • Create New VM (Do NOT install a new OS).
  • Allocate RAM/CPU matching the original Hyper-V specs.
  • Storage Controller: Attach existing .vdi.
  • Network: Set to NAT for isolated internet access.
[!] UEFI OVERRIDE: If the source was Generation 2, navigate to Settings > System > Motherboard and check Enable EFI. Failure to do so will result in a "No bootable medium found" error.

[ PHASE 2 ] VECTOR B: VMWARE WORKSTATION PROTOCOL

VMware utilizes the .vmdk format. We will deploy the qemu-img utility to execute the format translation.

STEP 2.1: Deploy QEMU-IMG

Verify the QEMU image converter is in your PATH or execute via absolute path.

powershell.exe
PS C:\> qemu-img.exe --version

STEP 2.2: Execute Disk Conversion

Translate vpc (VHD) to vmdk.

powershell.exe // conversion payload
PS C:\> qemu-img.exe convert -p -f vpc -O vmdk "D:\HyperV-Export\Virtual Hard Disks\abcd2.vhd" "D:\VMware\abcd2\abcd2_vmware.vmdk"

STEP 2.3: VMware VM Configuration

[!] FATAL ERROR PREVENTION: Do NOT double-click the .vmdk file. The .vmdk is just the disk. You must generate a .vmx configuration file via the VMware Wizard.
  • Open VMware Workstation → File > New Virtual Machine.
  • Select Custom (advanced).
  • Guest OS Installation: "I will install the operating system later".
  • Select the correct Windows Version (x64).
  • Disk Selection: Use an existing virtual disk → Browse to your .vmdk.
  • Format Prompt: Select Keep Existing Format.

STEP 2.4: Firmware & Boot Configuration

Navigate to VM > Settings > Options > Advanced.

  • Gen 1 Source: Set Firmware type to BIOS.
  • Gen 2 Source: Set Firmware type to UEFI. (Check Secure Boot settings if boot fails).

Boot the VM by opening the generated .vmx file. Install VMware Tools immediately upon successful OS load to stabilize virtual hardware drivers.

[ PHASE 3 ] ANOMALY RESOLUTION (TROUBLESHOOTING)

ANOMALY 01: "No bootable medium found" / "Operating System not found"

  • Root Cause: Firmware mismatch.
  • Fix: Verify Hyper-V Generation. Gen 2 requires EFI/UEFI enabled in target hypervisor. Gen 1 requires BIOS.
  • Check: Ensure the virtual disk is first in the Boot Order sequence.

ANOMALY 02: Windows Blue Screen (BSOD) on Boot

  • Root Cause: Hardware abstraction layer (HAL) or storage controller mismatch. The OS is expecting Hyper-V virtual hardware but is encountering VirtualBox/VMware chipsets.
  • Fix: Allow Windows to attempt self-repair. Check Storage Controller settings (SATA vs NVMe vs SCSI). Do not immediately assume disk corruption.

ANOMALY 03: "VMDK cannot be opened directly"

  • Root Cause: User attempted to execute the virtual disk as a standalone configuration.
  • Fix: Open VMware Workstation. Use File > Open and select the .vmx file, not the .vmdk.

ANOMALY 04: Inaccessible / Corrupted VDI

powershell.exe // disk forensics
PS C:\> & "C:\Program Files\Oracle\VirtualBox\VBoxManage.exe" showmediuminfo "D:\VirtualBox\MyVM\MyVM.vdi"
