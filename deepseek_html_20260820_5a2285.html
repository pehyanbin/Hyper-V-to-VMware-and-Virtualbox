⌘ Overview

You have a Hyper-V VM exported as a .vhd disk. This guide walks you through two separate migrations:

  • VirtualBox convert .vhd → .vdi using VBoxManage
  • VMware convert .vhd → .vmdk using qemu-img

Core principle: You are not importing the Hyper-V configuration. You are reusing the virtual disk and building a fresh VM configuration around it.

⏺ Hyper-V export structure:
MyVM\Virtual Hard Disks\MyVM.vhd  ← this is what you need.
.vmcx, .vmgs, .avhd  ← Hyper-V specific; ignore or backup.
⚠ If you see .avhd or .avhdx files — those are checkpoint differencing disks. Do not convert blindly. Identify the disk chain first (see Part 2 in each section).
◈ virtualbox migration ◈

01 VirtualBox — VHD → VDI

Part 1 — What you have

Your Hyper-V export contains a .vhd file inside Virtual Hard Disks\. That is the disk you will convert. The other files (.vmcx, .vmgs) are not used.

Part 2 — Check for checkpoints

Look inside Snapshots\ and Virtual Hard Disks\ for:

  • MyVM.vhd → good, continue
  • MyVM.avhd or .avhdx → stop; you have a checkpoint chain.
If you have .avhd files, do not convert the base .vhd alone. You may get an older state. Identify the current disk first.

Part 3 — Backup your VHD

Do not modify the original. Copy it to a working directory.

# example backup Copy-Item "D:\Hyper-V Export\MyVM\Virtual Hard Disks\MyVM.vhd" "D:\Backup\MyVM.vhd"

Part 4 — Check VirtualBox installation

VBoxManage.exe should be at:
C:\Program Files\Oracle\VirtualBox\VBoxManage.exe

If it's missing, repair/reinstall VirtualBox from the official Oracle installer.

Part 5 — Test VBoxManage

& "C:\Program Files\Oracle\VirtualBox\VBoxManage.exe" --version

Expected output: 7.1.x or similar.

Part 6 — Convert VHD → VDI

& "C:\Program Files\Oracle\VirtualBox\VBoxManage.exe" clonemedium disk \ "D:\Hyper-V Export\MyVM\Virtual Hard Disks\MyVM.vhd" \ "D:\VirtualBox\MyVM\MyVM.vdi" --format VDI

source ...\MyVM.vhd
dest ...\MyVM.vdi
format VDI (VirtualBox native)

Quotation marks matter. Paths contain spaces (Virtual Hard Disks). Quotes ensure the entire path is treated as one argument.

Part 7 — Verify the VDI

Test-Path "D:\VirtualBox\MyVM\MyVM.vdi" # should return True Get-Item "D:\VirtualBox\MyVM\MyVM.vdi" | Select-Object Name, Length

Part 8 — Create a new VM in VirtualBox

  1. Open VirtualBox → New
  2. Name: MyVM (or similar)
  3. Type: Microsoft Windows / Version: Windows 11 (64-bit) (adjust to your OS)
  4. RAM: match Hyper-V (e.g. 4096 MB or 8192 MB)
  5. CPU: match Hyper-V (e.g. 4 cores)
  6. Hard disk: Use an existing virtual hard disk file → select your .vdi

Part 9 — UEFI / Generation 2

If the original Hyper-V VM was Generation 2 (UEFI), enable:

Settings → System → Motherboard → Enable EFI (check)
Without EFI, you may see "No bootable medium found" even though the disk is fine.

Part 10 — Attach VDI (if not already)

  1. Select VM → Settings
  2. Storage → select the storage controller
  3. Add Hard Disk → Choose Existing Disk → select your .vdi

Part 11 — Networking

Start with NAT for simple internet access. Later switch to Bridged if needed.

Part 12 — Boot

Click Start. The first boot may take longer as Windows detects new virtual hardware.

✓ If Windows boots — migration complete. Keep the original .vhd as backup.
✗ "No bootable medium found" → check EFI is enabled, VDI is attached, and boot order has Hard Disk first.
◈ vmware migration ◈

02 VMware — VHD → VMDK

Part 1 — Understand your export

Same as before: the .vhd inside Virtual Hard Disks\ is your source disk. VMware cannot use Hyper-V's .vmcx configuration.

Part 2 — Check for checkpoints

Look for .avhd or .avhdx files. If present, identify the disk chain first.

Example: abcd2.vhd + abcd2-checkpoint1.avhd
Converting only abcd2.vhd may give you an older state.

Part 3 — Backup

Copy-Item "D:\HyperV-Export\Virtual Hard Disks\abcd2.vhd" "D:\HyperV-Backup\abcd2.vhd"

Part 4 — Install QEMU

Download qemu-img.exe from cloudbase.it or use a package manager. Place it in C:\Program Files\qemu\ or a folder in your PATH.

Part 5 — Test QEMU

"C:\Program Files\qemu\qemu-img.exe" --version

Part 6 — Inspect the VHD

"C:\Program Files\qemu\qemu-img.exe" info "D:\HyperV-Export\Virtual Hard Disks\abcd2.vhd"

You should see: file format: vpc and the virtual size.

Part 7 — Convert VHD → VMDK

"C:\Program Files\qemu\qemu-img.exe" convert -p -f vpc -O vmdk \ "D:\HyperV-Export\Virtual Hard Disks\abcd2.vhd" \ "D:\VMware\abcd2\abcd2_vmware.vmdk"

-f vpc input format (VHD)
-O vmdk output format (VMDK)
-p show progress

Wait for 100% — conversion time depends on disk size and storage speed.

Part 8 — Verify the VMDK

"C:\Program Files\qemu\qemu-img.exe" info "D:\VMware\abcd2\abcd2_vmware.vmdk"

Expected: file format: vmdk

Part 9 — Create VMware VM

Do not double-click the .vmdk. Instead:

  1. Open VMware Workstation
  2. File → New Virtual Machine
  3. Select Custom (advanced) → Next
  4. Hardware compatibility: default / recommended
  5. I will install the operating system later → Next
  6. Guest OS: Microsoft Windows → select your version (e.g. Windows 11 x64)
  7. Name: abcd2_vmware → Location: D:\VMware\abcd2\
  8. CPU / RAM: match Hyper-V (e.g. 4 cores, 8192 MB)
  9. Network: NAT (for first boot)
  10. Use an existing virtual disk → browse to your .vmdk
  11. Keep Existing Format (do not convert)
  12. Finish

Part 10 — Firmware: BIOS vs UEFI

Go to VM → Settings → Options → Advanced → Firmware type

  • Hyper-V Gen 1 → BIOS
  • Hyper-V Gen 2 → UEFI
Wrong firmware = "Operating System not found" or no boot manager.

Part 11 — Secure Boot

If your Gen 2 VM used Secure Boot, you may need to configure it in VMware. For first boot, try without Secure Boot, then enable if needed.

Part 12 — Boot order

VM → Settings → Options → Advanced → Boot Options
Ensure Hard Disk is at the top.

Part 13 — First boot

Click Power On. Be patient — Windows detects new virtual hardware.

✓ Windows boots — great! Let it finish device detection.

Part 14 — Install VMware Tools

After Windows is running, go to VM → Install VMware Tools. Restart after installation.

Part 15 — Check Device Manager

Win + X → Device Manager — look for unknown devices. VMware Tools should resolve most drivers.

Part 16 — Network check

Run ipconfig in the guest. You should see the VMware virtual adapter.

Part 17 — Windows Activation

Hardware changes may trigger reactivation. Have your license key ready.

Keep the original Hyper-V export until you've verified everything: boot, apps, files, network, services, activation.
◈ troubleshooting ◈

⚡ Common Issues

VirtualBox

  • "No bootable medium" → Enable EFI (Settings → System → Motherboard)
  • VDI inaccessible → run VBoxManage showmediuminfo "path.vdi"
  • Blue screen → different storage controller / CPU presentation; try changing the storage controller type in Settings → Storage
  • VBoxManage not found → repair/reinstall VirtualBox

VMware

  • "VMDK cannot be opened directly" → open the .vmx file, not the .vmdk
  • "Operating System not found" → check BIOS vs UEFI firmware
  • VM boots but crashes → check disk controller, firmware, install VMware Tools
  • QEMU can't read VMDK → re-run conversion; verify source VHD is not corrupted
Golden rule: Change one setting at a time. Don't toggle EFI, Secure Boot, and disk controller all at once.

✓ Pre-Flight Checklist

Before conversion

  • ☐ Locate the .vhd file
  • ☐ Check for .avhd / .avhdx (checkpoint chain)
  • ☐ Make a backup of the original VHD
  • ☐ Verify VirtualBox installation (VBoxManage.exe)
  • ☐ Install QEMU (qemu-img.exe) for VMware path
  • ☐ Determine Hyper-V Generation (Gen 1 = BIOS, Gen 2 = UEFI)

After conversion

  • ☐ Verify .vdi or .vmdk exists
  • ☐ Create new VM (do not import Hyper-V config)
  • ☐ Set correct firmware (BIOS / UEFI)
  • ☐ Attach the converted disk
  • ☐ Configure RAM / CPU (match Hyper-V)
  • ☐ Set boot order (Hard Disk first)
  • ☐ First boot → be patient
  • ☐ Install guest tools (VirtualBox Guest Additions / VMware Tools)
  • ☐ Keep original .vhd until fully verified
